# 02 — Архитектура

## 1. Общая схема

```
┌──────────────────────────────────────────────────────────────────┐
│ ПОТОК СОБЫТИЙ (выделенный Thread + собственный CFRunLoop)        │
│                                                                   │
│  CGEventTap (.cgSessionEventTap, .defaultTap, .headInsertEventTap)│
│         │                                                         │
│         ├─ событие наше собственное? → пропустить насквозь        │
│         ├─ .tapDisabledBy* → tapEnable(true), выход               │
│         ├─ flagsChanged → HotkeyDetector (двойной Shift, паника)  │
│         └─ keyDown → WordBuffer.append(keyCode, flags, time)      │
│                          ↓ только на границе слова                │
│                     передать в очередь решения и вернуться        │
│                                                                   │
│  Бюджет колбэка: < 50 мкс. Ничего блокирующего.                  │
└──────────────────────────────────────────────────────────────────┘
                              ↓ async
┌──────────────────────────────────────────────────────────────────┐
│ ОЧЕРЕДЬ РЕШЕНИЯ (serial DispatchQueue "decide")                  │
│                                                                   │
│  VetoGate ──── запрещено? ──→ конец, ничего не делаем             │
│      ↓ разрешено                                                  │
│  KeyMapper: коды клавиш → строка в текущей раскладке (t)          │
│                        → строка в целевой раскладке (t′)          │
│      ↓                                                            │
│  Scorer: Λ = [logP₄(t′|целевая) − logP₄(t|текущая)] / (L+1)       │
│          + словари + частотность + контекст двух слов             │
│      ↓                                                            │
│  Λ > порог(L)?  ── нет ──→ конец                                  │
│      ↓ да                                                         │
│  Classifier: σ(w·x) > 0.5 и доверие к приложению достаточно?      │
│      ↓ да                                                         │
│  Apply                                                            │
└──────────────────────────────────────────────────────────────────┘
                              ↓
┌──────────────────────────────────────────────────────────────────┐
│ ПРИМЕНЕНИЕ (отдельная очередь "apply", синтетические события)     │
│  TextReplacer → N × Backspace + keyboardSetUnicodeString(t′)      │
│  InputSourceService.select(целевая раскладка)                     │
│  UndoController.arm(оригинал, 5 секунд)                           │
│  Feedback: звук + мигание иконки                                  │
└──────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────┐
│ КОНТЕКСТ — обновляется вне потока клавиш, читается как кэш       │
│                                                                   │
│  SecureInputMonitor  таймер 1 с + на смене приложения            │
│  FocusMonitor        AXObserver: kAXFocusedUIElementChanged       │
│  AppMonitor          NSWorkspace.didActivateApplication           │
│  InputSourceService  CFNotification: смена раскладки              │
│                                                                   │
│  → атомарный снимок ContextSnapshot, который поток клавиш         │
│    читает одним чтением из памяти                                 │
└──────────────────────────────────────────────────────────────────┘
```

**Принцип разделения:** поток клавиш не имеет права ничего спрашивать у системы.
Всё, что ему нужно знать о мире — политика приложения, тип поля, состояние Secure
Input, активная раскладка — лежит в готовом виде в `HotContext`, который обновляют
другие подсистемы по своим событиям. Иначе один зависший Chrome подвешивает ввод на
всей машине.

Существенно, что `HotContext` — это ровно 64 бита без единой ссылки (см. §2): поток
клавиш читает его одним атомарным load, без блокировок и без ARC. Имя приложения и
bundle ID живут отдельно, в `ColdContext`, и потоку клавиш недоступны — иначе
«атомарная публикация» превратилась бы в неатомарное копирование `String` под
гонкой.

## 2. Модули

### `Core/EventTap/`

**`KeyTapService`** — владеет `CFMachPort`, потоком и run loop'ом. Отвечает за
создание, включение, сторожевой таймер, пересоздание после сна, обработку
`.tapDisabledBy*`. Наружу отдаёт поток событий через делегат. Единственное место
в проекте, где вообще упоминается `CGEvent.tapCreate`.

**`SyntheticEventSource`** — единственный `CGEventSource(stateID: .privateState)`
с меткой в `userData`. Умеет: отправить N Backspace, вставить строку, нажать
комбинацию. Знает про паузы между событиями (настраиваемые, по умолчанию 3 мс
для Backspace и 4 мс для вставки) и про то, что флаги модификаторов у синтетических
событий надо явно обнулять.

**`MouseMonitor`** — отдельный наблюдатель кликов мыши. Нужен потому, что клик
обязан сбрасывать буфер (иначе после перестановки каретки мышью синтетические Backspace
сотрут не то), а маска нашего tap'а сознательно ограничена клавиатурой — чтобы отказ
в правах был громким, а не тихим. Реализация:
`NSEvent.addGlobalMonitorForEvents(matching: [.leftMouseDown, .rightMouseDown,
.otherMouseDown])` — для событий мыши это не требует отдельного разрешения, и нам
здесь достаточно только наблюдать.

**`HotkeyDetector`** — конечный автомат распознавания двойного тапа модификатора.
Ест `flagsChanged` и `keyDown`, выдаёт события `.doubleTapShift`, `.panicToggle`.
Логика тапа описана в `00-DECISIONS.md`, Р1. Полностью тестируется без GUI: на вход
подаётся последовательность `(flags, timestamp)`.

### `Core/Layout/`

**`InputSourceService`** — перечисление раскладок (`TISCreateInputSourceList`),
текущая (`TISCopyCurrentKeyboardLayoutInputSource` — именно эта, а не
`...KeyboardInputSource`), переключение (`TISSelectInputSource`), подписка на смену
через `CFNotificationCenterGetDistributedCenter`. Хранит, когда пользователь
переключился сам — чтобы мы не переключали поверх.

**`KeyMapper`** — строит и кэширует двусторонние таблицы «код клавиши + модификаторы
↔ символ» для каждой включённой раскладки, через `UCKeyTranslate` над
`kTISPropertyUnicodeKeyLayoutData`. Кэш по ключу `layoutID`. Умеет отвечать на
главный вопрос: «вот последовательность нажатий — что получится в раскладке X».
Обрабатывает мёртвые клавиши (двойной вызов `UCKeyTranslate`) и NULL-данные
у методов ввода.

### `Core/Context/`

**`SecureInputMonitor`** — опрашивает `IsSecureEventInputEnabled()`. При изменении
на true немедленно шлёт всем «стоп» и вызывает очистку буфера. Умеет доставать
предполагаемый PID виновника из IORegistry (`kCGSSessionSecureInputPID`) для текста
в меню — с оговоркой, что значение ненадёжно.

**`FocusMonitor`** — держит `AXObserver` на текущем фронтовом приложении, слушает
`kAXFocusedUIElementChangedNotification` и `kAXFocusedWindowChangedNotification`.
На каждое событие обновляет кэш `(role, subrole, isSecure)` одним пакетным вызовом
`AXUIElementCopyMultipleAttributeValues`. Обязательно ставит
`AXUIElementSetMessagingTimeout(element, 0.2)` (первый аргумент — сам элемент).
Пересоздаётся при смене приложения.

**`AppMonitor`** — следит за сменой активного приложения через
`NSWorkspace.shared.notificationCenter`, `didActivateApplicationNotification`.
Инициирует пересоздание `FocusMonitor` под новый pid и обновление снимка контекста.

**`AppPolicyStore`** — по bundle ID отдаёт режим: выключено / только хоткей / автомат,
плюс накопленную статистику доверия (α, β). Системные исключения зашиты в код
и помечены как неудаляемые.

**`ContextSnapshot`** — снимок мира, публикуемый вне потока клавиш. Разделён на две
части, и это **не украшение, а необходимость**: структуру со `String` нельзя прочитать
атомарно, а поток клавиш обязан читать без блокировок.

```swift
// ГОРЯЧАЯ часть: всё, что нужно потоку клавиш. Ровно 64 бита, публикуется
// одним атомарным store и читается одним атомарным load. Ни ссылок, ни ARC.
struct HotContext {                   // упаковано в UInt64
    var isSecureInput: Bool           //  1 бит
    var policy: AppPolicy             //  2 бита  выкл / хоткей / автомат
    var fieldRole: FieldRole          //  3 бита  .text .secure .code .terminal .unknown
    var sourceLayoutSlot: UInt8       //  8 бит   индекс в таблице раскладок KeyMapper
    var targetLayoutSlot: UInt8       //  8 бит
    var generation: UInt32            // 32 бита  для сверки на очереди решения
}

// ХОЛОДНАЯ часть: читает только очередь решения, под os_unfair_lock.
// Поток клавиш её не касается никогда.
struct ColdContext {
    let bundleID: String
    let appName: String
    let generation: UInt32
}
```

Очередь решения читает обе части и **сверяет `generation`**: если между постановкой в
очередь и обработкой контекст сменился, решение отменяется. Это дешёвая замена
блокировке и единственная защита от «пользователь переключил окно, пока мы думали».

### `Core/Detect/`

**`WordBuffer`** — кольцевой буфер `[KeyRecord]` фиксированной ёмкости (64 записи,
value-тип, без аллокаций). Хранит **коды клавиш, а не символы** — это принципиально,
потому что символ зависит от раскладки, а мы как раз выясняем, какая была нужна.
Отслеживает границы слов, чтобы уметь отдать последние 1, 2 или N слов.
Метод `wipe()` делает `memset_s`.

**`NGramModel`** — обёртка над `mmap`-нутым блобом. Плотная таблица триграмм для
быстрой инкрементальной оценки на лету, плотная таблица 4-грамм для окончательного
решения. **Обе плотные** — `u8[V³]` и `u8[V⁴]`, индекс считается арифметикой, без
поиска (см. §5 и `05-DATA.md` §5, где разреженное хранение разобрано и отвергнуто:
оно экономит место только на маленьком обучающем наборе, а взамен даёт бинарный поиск
на горячем пути и непредсказуемый размер файла). Логарифмы вероятностей квантованы
в `UInt8` (шаг 1/8 наты).

**`Lexicon`** — DAWG со словоформами. Проверка вхождения и проверка «является ли
префиксом какого-нибудь слова» (пригодится для ранней оценки). Плюс таблица
частотности по шкале Zipf для известных слов.

**`VetoGate`** — упорядоченный список жёстких запретов, выполняется до любого
скоринга, потому что дёшев. Порядок важен: сначала самое дешёвое и самое критичное.
```
1. Secure Input включён
2. Политика приложения запрещает
3. Поле — secure / терминал / редактор кода
4. Слово короче минимума (в одиночку)
5. Слово в пользовательском списке «не менять»
6. Похоже на адрес / почту / IP / MAC / путь
7. Содержит цифры рядом с буквами
8. camelCase / snake_case / kebab-case
9. Длина > 24
10. Похоже на пароль (смешанный регистр + цифры + знаки, длина > 12)
11. ALL CAPS длиной ≤ 4 (аббревиатура)
```

**`Scorer`** — считает Λ и все признаки. Чистая функция от `([KeyRecord], модели,
контекст)`. Никаких побочных эффектов, полностью покрывается юнит-тестами.

**`Classifier`** — логистическая регрессия. Только фильтрует, не разрешает.

### `Core/Apply/`

**`TextReplacer`** — выбирает стратегию по контексту и выполняет замену.
```swift
protocol ReplacementStrategy {
    func canHandle(_ ctx: ContextSnapshot) -> Bool
    func replace(deleting: Int, with: String, ctx: ContextSnapshot) throws
}
```
Реализации: `AccessibilityStrategy` (нативные поля), `SyntheticTypingStrategy`
(по умолчанию), `PasteboardStrategy` (только по явному включению).
Порядок выбора и запись «в этом приложении первая стратегия не сработала» —
в `TextReplacer`, чтобы второй раз не пробовать заведомо неработающее.

**`UndoController`** — хранит последнюю замену: что было, что стало, где, когда.
Живёт 5 секунд, потом забывается. Откат = обратная замена + сигнал обучению.

### `Core/Learn/`

**`FeedbackStore`** — счётчики «отменено / принято» по слову и по приложению,
веса классификатора. Хранится в `~/Library/Application Support/Lazy Switcher/`
в виде маленького SQLite или plist. Запись всегда отложенная, в фоне, никогда
из потока клавиш. **Хранит только слова, участвовавшие в исправлениях, и только
те, где пользователь явно выразил мнение.** Не история набора.

**`UserLexicon`** — списки «никогда» и «всегда» с указанием происхождения записи.

**`AppTrust`** — бета-распределение по приложению, отдаёт нижнюю доверительную
границу, по которой решается, можно ли в этом приложении автоматически заменять.

### `App/`

**`AppDelegate`** — сборка зависимостей, порядок запуска, проверка прав.
**`MenuBarController`** — `NSStatusItem`, меню, состояния иконки. Держать сильную
ссылку, иначе иконка исчезнет.
**`SettingsWindowController`** — четыре вкладки, AppKit.
**`OnboardingWindowController`** — четыре шага первого запуска.
**`PermissionsCoordinator`** — вся логика вокруг разрешений: проверка, запрос,
распознавание «залипшего» состояния, ссылки в Системные настройки.

## 3. Порядок запуска

```
1. Проверить, что приложение в /Applications; если нет — предложить перенести
   (иначе App Translocation сломает сохранение настроек)
2. Загрузить настройки
3. Проверить разрешения (порядок важен, см. ниже):
   CGPreflightListenEventAccess() && CGPreflightPostEventAccess()
   └─ затем однократная перекрёстная проверка пробным tap'ом
   ├─ нет → показать онбординг, дальше не идти
   └─ да  → продолжить
4. mmap моделей (лениво: только при первой необходимости, чтобы старт был мгновенным)
5. Построить таблицы раскладок
6. Поднять контекстные наблюдатели
7. Поднять поток event tap
8. Показать иконку в строке меню
```

**Основная проверка — `CGPreflight*`, пробный tap только как перекрёстная.**
`AXIsProcessTrusted()` в решении не участвует вовсе: он возвращает true даже после
отзыва доступа, а уведомление `com.apple.accessibility.api` не приходит, если
пользователь удалил приложение из списка, а не выключил галочку. Пробный tap —
надёжный, но дорогой сигнал с побочными эффектами (`04-PLATFORM.md` §1.2: частое
пересоздание tap'ов само по себе ненадёжно), поэтому он делается один раз на старте
и далее только когда `CGPreflight*` меняет ответ, а не по таймеру.

## 4. Потоки

| Поток | Что делает | Бюджет | Чего нельзя |
|---|---|---|---|
| `eventtap` (Thread + CFRunLoop) | tap, буфер, распознавание хоткеев | < 50 мкс | AX, буфер обмена, аллокации, локи main |
| `decide` (serial queue) | скоринг и решение | < 2 мс | блокировать дольше 50 мс |
| `apply` (serial queue) | синтетические события, переключение раскладки | 50–150 мс | трогать состояние решения без синхронизации |
| `main` | интерфейс, AXObserver, наблюдатели | — | тяжёлые вычисления |
| `persist` (utility queue) | запись обучения на диск | — | что угодно синхронное |

**Замена вынесена в отдельную очередь.** Она по своей природе долгая: между
синтетическими нажатиями нужны паузы в несколько миллисекунд, и на слове из десяти
букв это уже сотня миллисекунд. Держать это на очереди решения нельзя — следующее
слово успеет прийти.

`AXUIElement` не является `Sendable` — при использовании Swift Concurrency
оборачивать в `@unchecked Sendable` бокс.

## 5. Формат данных моделей

Один файл на язык, `mmap` только для чтения, little-endian:

```
[magic "LSM1"][u32 версия][u32 код языка][u32 V][таблица секций]
  §DAWG  u32 количество рёбер, [u32 ребро]*
  §TRI   u8[V³]      плотная таблица триграмм
  §QUAD  u8[V⁴]      плотная таблица 4-грамм
  §UNI   u32 количество, отсортированные [u32 индекс][u8 zipf]*
```

Никакого JSON и plist при старте — только `mmap`.

## 6. Что тестируется без GUI

Это важно для планирования: почти вся логика проверяема автоматически.

| Компонент | Тест |
|---|---|
| `HotkeyDetector` | последовательность `(flags, timestamp)` → ожидаемые события |
| `KeyMapper` | коды клавиш → строка, на реальных данных раскладок системы |
| `WordBuffer` | границы слов, сброс, ёмкость |
| `Scorer` | корпус из `Tools/eval` → метрики точности |
| `VetoGate` | таблица «строка → запрещено/разрешено», сотни случаев |
| `Classifier` | сходимость на синтетических данных, монотонность |
| `UndoController` | восстановление байт-в-байт |

Требует ручной проверки: перехват, замена в конкретных приложениях, разрешения,
Secure Input, звук, иконка. Сценарии — в `08-TESTING.md`.
