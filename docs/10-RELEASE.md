# 10 — Выпуск версии

Пошагово, чтобы ничего не забыть. Каждый шаг проверяем, а не надеемся.

## 1. Поднять номер версии

`MARKETING_VERSION` в `LazySwitcher.xcodeproj/project.pbxproj` — **в двух местах**
(Debug и Release). Проверить:

```bash
grep -c "MARKETING_VERSION = 1.1" LazySwitcher.xcodeproj/project.pbxproj   # должно быть 2
```

## 2. Пересобрать модели, если менялись словари или алфавит

```bash
./Tools/build-models/all.sh
```

Сборка детерминирована: если словари не менялись, файлы получатся побайтово теми
же. Расхождение без изменения входа — повод разбираться, а не пересобирать ещё раз.

## 3. Прогнать тесты

```bash
xcodebuild test -project LazySwitcher.xcodeproj -scheme LazySwitcher \
  -destination 'platform=macOS,arch=arm64'
```

Отдельно посмотреть замер точности — он пишется в `eval/report.md`. Ложные
срабатывания от шести символов обязаны быть 0.00%. Если нет — не выпускать.

## 4. Собрать, подписать, проверить

```bash
xcodebuild build -project LazySwitcher.xcodeproj -scheme LazySwitcher \
  -configuration Release -derivedDataPath build
./scripts/sign.sh "build/Build/Products/Release/Lazy Switcher.app"
./scripts/audit-release.sh
./scripts/audit-network.sh
```

`audit-release.sh` смотрит **собранный бинарник**, а не исходники: между
«в коде стоит `#if DEBUG`» и «в бинарнике этого нет» лежит вся конфигурация
сборки. Он обязан сказать «Всё чисто».

## 5. Собрать образ

```bash
./scripts/make-dmg.sh "build/Build/Products/Release/Lazy Switcher.app"
```

## 6. Выложить релиз

Тег обязан совпадать с `MARKETING_VERSION`, иначе проверка обновлений будет
предлагать обновиться на уже установленную версию. `UpdateChecker` снимает
ведущую `v`, так что и `1.1`, и `v1.1` подойдут.

```bash
git tag v1.1 && git push origin v1.1
gh release create v1.1 dist/LazySwitcher-1.1.dmg \
  --title "1.1" --notes-file NOTES.md
```

Без `gh` — то же самое через веб-интерфейс: Releases → Draft a new release.

## 7. Проверить, что обновление видно

В приложении: «О программе» → «Проверить сейчас». Должно показать новую версию.
Если репозиторий приватный, проверка работать **не будет**: она ходит в публичный
API без токена. Это осознанное ограничение — токен в приложении был бы хуже.

---

## Чего в выпуске нет и почему

**Нотаризации.** Нужен платный аккаунт разработчика. Без неё macOS показывает
«не удаётся проверить разработчика», и человеку приходится один раз зайти в
Системные настройки. Инструкция лежит внутри образа.

**Автоматической установки обновлений — теперь есть, и вот на каких условиях.**

Раньше здесь стояло «мы такого не делаем», и основание было верное: программа с
доступом к Универсальному доступу, умеющая заменять собственный бинарник, — это
самообновляющийся кейлоггер, и просить верить в его добросовестность значит
просить слишком много.

Изменилась не опасность, а доказуемость. Обновление устанавливается, только если
скачанное приложение удовлетворяет **designated requirement работающего**: тот же
идентификатор, тот же сертификат. Закрытый ключ от этого сертификата существует в
одной связке ключей и нигде не опубликован, поэтому подменённый релиз на GitHub,
угнанный домен и перехваченное соединение одинаково упираются в отказ, а не в
установку.

Три вещи из этого следуют и не обсуждаются:

- требование читается у **работающего** бинарника, никогда у скачанного —
  иначе загрузка ручается сама за себя;
- проверка идёт до того, как что-либо копируется, и повторяется на копии, потому
  что устанавливается именно она, а не проверенный оригинал;
- отказ громкий и полный: ни запасного пути, ни «всё равно установить».

Закреплено тестами (`UpdaterSignatureTests`), из которых главный — что приложение
с **исправной** подписью Apple отвергается. Проверка, которая спрашивает «валидна
ли подпись» вместо «наша ли она», приняла бы его.

Если эти тесты когда-нибудь перестанут проходить, автообновление надо выключать,
а не чинить обход.

## Обязательный шаг: обновить «что нового»

Перед сборкой версии перепишите **оба** файла:

```
LazySwitcher/ru.lproj/WhatsNew.txt
LazySwitcher/en.lproj/WhatsNew.txt
```

Это то, что человек увидит сам, один раз, сразу после обновления. Пишите для
того, кто не читал ни коммитов, ни этих документов: что изменилось с его точки
зрения и почему это его касается. **Не** технический разбор — он остаётся в
`00-DECISIONS.md` и в сообщении коммита (Р15).

Под заметками показывается история про лень — она выбирается из номера версии
сама (`Stories`, Р16). Если к очередной истории нарисована картинка, добавьте её
в `Tools/story-art.swift` и в `Assets.xcassets`; без картинки история покажется
одним текстом, и это нормально.

Файлы лежат **внутри приложения** и в сеть за ними никто не ходит — окно
работает офлайн и с выключенной проверкой обновлений (правило 3 не нарушается).

Проверить, что текст попал в сборку:

```bash
find "build/Build/Products/Release/Lazy Switcher.app" -name WhatsNew.txt
```

Должны быть обе локализации. Тест `testNotesAreBundled` проверяет то же самое.

## Проверка, что обновление действительно доедет

Делать после каждой публикации. Проверяет не «файл выложен», а «установленная
старая версия сможет поставить новую» — это разные утверждения, и второе никогда
не проверялось само.

```bash
VER=$(ls -t dist/*.dmg | head -1 | sed 's/.*LazySwitcher-//;s/\.dmg//')
curl -s https://api.github.com/repos/Terranova1000/LazySwitcher/releases/latest \
  | python3 -c "import json,sys; d=json.load(sys.stdin); print(d['tag_name'], [a['name'] for a in d['assets']])"
```

Ожидание: тег — новая версия, среди активов есть `LazySwitcher-$VER.dmg`.
Приложение спрашивает ровно этот адрес и берёт `tag_name`.

Затем — главное: подпись. Обновление проверяет скачанный бандл **требованием
работающего бинарника**, и если сертификат сменился, обновление молча откажет.

```bash
hdiutil attach "dist/LazySwitcher-$VER.dmg" -nobrowse -quiet -mountpoint /tmp/rel
DR=$(codesign -d -r- "/Applications/Lazy Switcher.app" | grep '^designated')
codesign --verify --deep --strict -R "=${DR#designated => }" "/tmp/rel/Lazy Switcher.app"
hdiutil detach /tmp/rel -quiet -force
```

Пустой вывод и нулевой код возврата — установленная версия примет новую. Ошибка
означает, что все, кто уже пользуется приложением, обновиться не смогут, и узнают
об этом молчанием.
