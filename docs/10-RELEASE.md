# 10 — Выпуск версии

Пошагово, чтобы ничего не забыть. Каждый шаг проверяем, а не надеемся.

## 1. Поднять номер версии

`MARKETING_VERSION` в `LazySwitcher.xcodeproj/project.pbxproj` — **в двух местах**
(Debug и Release). Проверить:

```bash
grep -c "MARKETING_VERSION = 1.1" LazySwitcher.xcodeproj/project.pbxproj   # должно быть 2
```

## 2. Пересобрать модели, если менялись словари или алфавит

```bash
./Tools/build-models/all.sh
```

Сборка детерминирована: если словари не менялись, файлы получатся побайтово теми
же. Расхождение без изменения входа — повод разбираться, а не пересобирать ещё раз.

## 3. Прогнать тесты

```bash
xcodebuild test -project LazySwitcher.xcodeproj -scheme LazySwitcher \
  -destination 'platform=macOS,arch=arm64'
```

Отдельно посмотреть замер точности — он пишется в `eval/report.md`. Ложные
срабатывания от шести символов обязаны быть 0.00%. Если нет — не выпускать.

## 4. Собрать, подписать, проверить

```bash
xcodebuild build -project LazySwitcher.xcodeproj -scheme LazySwitcher \
  -configuration Release -derivedDataPath build
./scripts/sign.sh "build/Build/Products/Release/Lazy Switcher.app"
./scripts/audit-release.sh
./scripts/audit-network.sh
```

`audit-release.sh` смотрит **собранный бинарник**, а не исходники: между
«в коде стоит `#if DEBUG`» и «в бинарнике этого нет» лежит вся конфигурация
сборки. Он обязан сказать «Всё чисто».

## 5. Собрать образ

```bash
./scripts/make-dmg.sh "build/Build/Products/Release/Lazy Switcher.app"
```

## 6. Выложить релиз

Тег обязан совпадать с `MARKETING_VERSION`, иначе проверка обновлений будет
предлагать обновиться на уже установленную версию. `UpdateChecker` снимает
ведущую `v`, так что и `1.1`, и `v1.1` подойдут.

```bash
git tag v1.1 && git push origin v1.1
gh release create v1.1 dist/LazySwitcher-1.1.dmg \
  --title "1.1" --notes-file NOTES.md
```

Без `gh` — то же самое через веб-интерфейс: Releases → Draft a new release.

## 7. Проверить, что обновление видно

В приложении: «О программе» → «Проверить сейчас». Должно показать новую версию.
Если репозиторий приватный, проверка работать **не будет**: она ходит в публичный
API без токена. Это осознанное ограничение — токен в приложении был бы хуже.

---

## Чего в выпуске нет и почему

**Нотаризации.** Нужен платный аккаунт разработчика. Без неё macOS показывает
«не удаётся проверить разработчика», и человеку приходится один раз зайти в
Системные настройки. Инструкция лежит внутри образа.

**Автоматической установки обновлений.** Приложение только сообщает о новой
версии и открывает страницу. Механизм, который сам скачивает и подменяет бандл с
доступом к Универсальному доступу, — это ровно то, чему не стоит доверять на
слово, и мы такого не делаем.
