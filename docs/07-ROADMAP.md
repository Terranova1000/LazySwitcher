# 07 — План работ

Этапы идут строго по порядку. Следующий не начинается, пока критерии предыдущего не
выполнены — здесь это важнее обычного, потому что каждый следующий этап опирается на
подтверждённое поведение системы, а не на предположение.

Отмечать галочки прямо в этом файле по мере выполнения.

---

## M0 — Разведка боем (полдня)

Проверяем самые опасные предположения **до** того, как написан код, который на них
опирается. Одно голое приложение, никакой логики.

- [ ] Пустой AppKit-проект, `LSUIElement`, иконка в строке меню
- [ ] Скрипт `make-cert.sh`, сертификат создан и помечен доверенным
- [ ] Приложение подписано, `codesign -d -r-` показывает DR по сертификату
- [ ] `CGEventTap` создаётся, ловит нажатия, печатает коды клавиш
- [ ] **Ключевой эксперимент:** выдать доступ, пересобрать с изменённым кодом,
      переустановить, проверить, что доступ сохранился
- [ ] Проверить `IsSecureEventInputEnabled()` на живом примере
      (`python3 -c 'import getpass; getpass.getpass()'` в терминале)
- [ ] Проверить, что `flagsChanged` действительно приходят при Secure Input,
      а `keyDown` — нет
- [ ] Замерить, сколько времени в колбэке приводит к `tapDisabledByTimeout`

**Критерий готовности:** известно, сохраняются ли разрешения при пересборке. Если
нет — останавливаемся и придумываем другое решение, вся стратегия обновлений от
этого зависит.

## M1 — Ядро перехвата (2–3 дня)

- [ ] `KeyTapService`: выделенный поток, run loop, обработка `.tapDisabledBy*`
- [ ] Сторожевой таймер 5 с + реакция на пробуждение из сна
- [ ] `SyntheticEventSource` с меткой в `userData` и `.privateState`
- [ ] Отбрасывание собственных событий первой строкой колбэка
- [ ] `WordBuffer`: кольцевой буфер кодов клавиш, границы слов, `wipe()`
- [ ] Все правила сброса буфера (модификаторы, каретка, мышь, фокус, простой)
- [ ] `SecureInputMonitor`
- [ ] `PermissionsCoordinator`: `CGPreflightListenEventAccess` / `CGPreflightPostEventAccess`
      как основная проверка, пробный tap — как перекрёстная. Не полагаться на
      `AXIsProcessTrusted`, он врёт после отзыва доступа
- [ ] `MouseMonitor` — сброс буфера по клику мыши

**Критерий:** приложение сутки работает фоном, ловит нажатия, ничего не тормозит,
не отваливается после сна и после блокировки экрана. Тест на живучесть обязателен —
именно здесь у аналогов проявляется «вчера работало».

## M2 — Раскладки (1–2 дня)

- [ ] `InputSourceService`: перечисление, текущая, переключение, подписка на смену
- [ ] `KeyMapper`: таблицы через `UCKeyTranslate`, кэш по `layoutID`
- [ ] Обработка мёртвых клавиш (двойной вызов) и NULL-данных
- [ ] Конверсия последовательности кодов клавиш в строку любой раскладки
- [ ] Юнит-тесты на реальных данных раскладок системы
- [ ] Проверка на нестандартных раскладках: Russian — PC, ISO-клавиатура

**Критерий:** для любой последовательности нажатий получаем корректный текст в обеих
раскладках, включая символы с Shift (`ж` = `;`, `Ж` = `:`, `б` = `,`, `Б` = `<`).
Ни одной захардкоженной буквы в коде.

попадает в исключения. Промежуточных состояний быть не должно.

**Критерий:** на отложенном корпусе ложных срабатываний **0.00%** для слов от 6

это главная метрика продукта. Отчёт с числами сохранить в `eval/`.

## Ориентир по срокам

Примерно 15–20 рабочих дней работы плюс неделя обкатки на M6, которая идёт
параллельно с M7. То есть около месяца календарного времени, если заниматься подряд.
Самое непредсказуемое — M4: поведение синтетического ввода в чужих приложениях
невозможно предсказать по документации, только проверить.
