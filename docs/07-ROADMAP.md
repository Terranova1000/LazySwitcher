# 07 — План работ

Этапы идут строго по порядку. Следующий не начинается, пока критерии предыдущего не
выполнены — здесь это важнее обычного, потому что каждый следующий этап опирается на
подтверждённое поведение системы, а не на предположение.

Отмечать галочки прямо в этом файле по мере выполнения.

---

## M0 — Разведка боем (полдня)

Проверяем самые опасные предположения **до** того, как написан код, который на них
опирается. Одно голое приложение, никакой логики.

- [x] Пустой AppKit-проект, `LSUIElement`, иконка в строке меню
- [x] Скрипт `make-cert.sh`, сертификат создан (доверенным помечать не нужно — Н1/Н2)
- [x] Приложение подписано, `codesign -d -r-` показывает DR по сертификату
- [x] `CGEventTap` создаётся, ловит настоящие нажатия
- [x] **Ключевой эксперимент:** выдать доступ, пересобрать с изменённым кодом,
      переустановить, проверить, что доступ сохранился — **сохранился** (Н5)
- [ ] Проверить `IsSecureEventInputEnabled()` на живом примере
      (`python3 -c 'import getpass; getpass.getpass()'` в терминале)
- [ ] Проверить, что `flagsChanged` действительно приходят при Secure Input,
      а `keyDown` — нет
- [x] Замерить, сколько времени в колбэке приводит к `tapDisabledByTimeout` — 950…1000 мс (Н7)

**Критерий готовности: выполнен.** Разрешения при пересборке сохраняются (Н5),
стратегия обновлений подтверждена, можно идти дальше.

Осталось два пункта про Secure Input — они требуют настоящей клавиатуры на экране
блокировки и закрываются одной минутой ручной проверки, но гейт этапа не держат:
от их результата зависит строгость хоткея, а не архитектура.

именно здесь у аналогов проявляется «вчера работало».

- [x] `VetoGate` со всеми правилами и таблицей тестов (19 тестов)
- [x] Проверить определение поля пароля: Safari ✅, Chrome ❌, Firefox ❌ — см. Н10 и вопрос O7

**Критерий выполнен.** В Safari тип поля определяется правильно, включая пароль.
В Chrome и Firefox определить не удаётся — и там приложение честно возвращает
«не знаю» и не делает ничего.

Но выполненный критерий здесь не значит решённую задачу: молчать в Chrome
безопасно и бесполезно одновременно. Продуктовое решение — вопрос **O7**,
принять до начала M4.

## Ориентир по срокам

Примерно 15–20 рабочих дней работы плюс неделя обкатки на M6, которая идёт
параллельно с M7. То есть около месяца календарного времени, если заниматься подряд.
Самое непредсказуемое — M4: поведение синтетического ввода в чужих приложениях
невозможно предсказать по документации, только проверить.
